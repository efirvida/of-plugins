# `turbinesFoam/geometry/` — deterministic turbine geometry pipeline

Per-component STL surfaces for the actuator surface model (ASM), generated from
committed gmsh sources by a Python generator. The pipeline is deterministic
(pinned gmsh, fixed options), so a committed STL can always be traced back to
its inputs — and regenerated byte-for-byte.

S1 generates the **nacelle/hub** surface consumed by `nacelleSurfaceSource`.
Blade STLs are reserved for S2 (blade surface model) and are not generated here.

## Layout

```
geometry/
├── README.md             # this file
├── PROVENANCE.md         # sources, generator, input/artefact sha256
├── src/
│   ├── nacelle.geo       # gmsh: hemisphere (R) + cylinder (6R), OpenCASCADE
│   └── makeGeometry.py   # CLI: generate | --check | --component | --gmsh
├── stl/
│   └── nacelle.stl       # committed binary STL (2616 triangles)
└── metadata/
    └── nacelle.json      # per-node normals + areas; blade fields reserved
```

## Usage

```sh
cd turbinesFoam/geometry

python3 src/makeGeometry.py                          # generate all components
python3 src/makeGeometry.py --component nacelle      # one component (S1)
python3 src/makeGeometry.py --check                  # verify, never writes
python3 src/makeGeometry.py --gmsh /path/to/gmsh     # explicit gmsh executable
```

`--gmsh` defaults to the first `gmsh` on `PATH`. `--check` is the CI/PR gate: it
regenerates the component into a temporary directory, byte-compares the STL and
the metadata JSON against the committed artefacts, and verifies that
`PROVENANCE.md` records their current sha256 values.

Exit codes: `0` clean, `1` stale or failed generation, `2` gmsh missing, not
runnable, or not the pinned version (`--check` only).

A run with successful generation prints the input sha256 and the STL sha256;
`PROVENANCE.md` must record both (update it after regenerating, then re-run
`--check`).

## Components

| Component | Status | Notes |
|---|---|---|
| `nacelle` | generated in S1 | hemisphere (`R`, upstream) + cylinder (`R` radius, `6R` length), closed by a flat cap at the downstream end. 2616 triangles (paper target ~2652, −1.4 %). |
| `blade0`, `blade1`, `blade2` | **deferred to S2** | The layout (`stl/`, `metadata/`), the `--component` flag and the metadata schema already reserve them. Asking for one exits non-zero with the S2 deferral message; no blade STL is generated in S1. |

Adding a component means adding `src/<name>.geo` and one entry in
`makeGeometry.COMPONENTS` plus its reserved name; the STL/metadata paths and the
`--check` flow come from the registry.

## Metadata schema (`metadata/nacelle.json`)

```json
{
  "component": "nacelle",
  "format_version": 1,
  "generator": {"script": "src/nacelle.geo", "gmsh_version": "4.15.2"},
  "input_sha256": "<sha256 of src/nacelle.geo + parameter block>",
  "units": "m",
  "n_triangles": 2616,
  "parameters": {"R": 1.0, "cylinderRatio": 6.0, "meshSizeRatio": 0.2125},
  "stl_sha256": "<sha256 of stl/nacelle.stl>",
  "nodes": [
    {"index": 0, "normal": [-0.995209, 0.0141688, 0.0967404], "area": 0.0189569}
  ],
  "_reserved": {"blade": {"radial_station": null, "chord_fraction": null}}
}
```

One node per STL triangle, in STL order: `index` is the triangle index (the
order a layout loader sees), `normal` is the outward unit normal of that
triangle, `area` its area. `_reserved.blade` reserves the per-node radial
station / chord fraction mapping the S2 blade surfaces will need. Floats are
rounded to 6 significant digits (within the float32 resolution of the binary
STL).

`n_triangles`/`nodes` describe the *surface* nodes a `nacelleSurfaceSource`
consumes (the sampler uses triangle centroids as its node set), not the STL's
vertices.

## Determinism requirements

- The gmsh version is pinned (**4.15.2**, recorded in `metadata/*.json` and
  `PROVENANCE.md`). `--check` refuses to certify regeneration with any other
  version (exit `2`) instead of reporting a false staleness.
- The mesh seed and options live in `src/<component>.geo`; the parameters marked
  `primary:` are parsed into the metadata and the input sha256.
- The generator re-serializes gmsh's mesh in a canonical order (cyclically
  minimal vertex order per triangle, triangles sorted) and writes the binary STL
  itself, with a fixed header and recomputed facet normals. gmsh's element
  ordering is not stable across environments, so without this step the same mesh
  could produce different bytes; with it, the committed STL depends only on the
  mesh geometry.
- `--check` never modifies the tree — it regenerates into a temporary
  directory. Tests rely on this by copying the whole `geometry/` tree to a
  temporary location and corrupting the copy.
- gmsh must be *runnable*, not merely installed: the pip module links
  `libGLU.so.1`/`libGL.so.1`. On SDumont, `module load glu/9.0.2_gnu` (see
  `PROVENANCE.md`). Without it, `tests/test_nacelle_data.py` skips the
  regeneration checks with an explicit reason.

## Consuming the STL

`nacelleSurfaceSource` reads `stl/nacelle.stl` directly through OpenFOAM's
`triSurface` (`geometry` key in the `nacelle {}` subdict / standalone
`fvOptions` entry). The STL is in metres, with the downstream end of the body at
the streamwise origin `x = 0` and the nose pointing upstream to `x = -7R`, which
is the frame the validation case in `validation/nacelle-asn/` expects (`R = 1 m`,
`Re = 1000`).

The generation recipe, source references and the resolved cylinder length are
recorded in `PROVENANCE.md`; `tests/test_nacelle_data.py` guards the committed
artefacts (schema, geometry, hashes, provenance) without OpenFOAM.
