# `turbinesFoam/geometry/` — deterministic turbine geometry pipeline

Per-component STL surfaces for the actuator surface model (ASM), generated from
committed sources by a Python generator with a per-component builder registry.
Every component is deterministic, so a committed STL can always be traced back
to its inputs — and regenerated byte-for-byte.

Two components are generated:

- `nacelle` — gmsh-driven (pinned 4.15.2) from the committed `src/nacelle.geo`;
  consumed by `nacelleSurfaceSource`.
- `phaseVI_blade` — a pure-Python structured loft (`src/blade_phasevi.py`) over
  the committed Phase VI stations and S809 coordinates; one STL serves both
  identical Phase VI blades.

## Layout

```
geometry/
├── README.md             # this file
├── PROVENANCE.md         # sources, generator routes, input/artefact sha256
├── src/
│   ├── nacelle.geo       # gmsh: hemisphere (R) + cylinder (6R), OpenCASCADE
│   ├── blade_phasevi.py  # Python: S809 parse + structured loft (no gmsh)
│   └── makeGeometry.py   # CLI: generate | --check | --component | --gmsh
├── stl/
│   ├── nacelle.stl       # committed binary STL (2616 triangles)
│   └── phaseVI_blade.stl # committed binary STL (3000 triangles, wetted)
└── metadata/
    ├── nacelle.json      # per-node normals + areas; `_reserved` blade mapping
    └── phaseVI_blade.json # per-node normals + areas + radial_station/chord_fraction
```

## Usage

```sh
cd turbinesFoam/geometry

python3 src/makeGeometry.py                              # default component (nacelle)
python3 src/makeGeometry.py --component nacelle          # gmsh route
python3 src/makeGeometry.py --component phaseVI_blade    # Python route (no gmsh)
python3 src/makeGeometry.py --check                      # verify, never writes
python3 src/makeGeometry.py --check --component phaseVI_blade
python3 src/makeGeometry.py --gmsh /path/to/gmsh         # explicit gmsh executable
```

`--gmsh` defaults to the first `gmsh` on `PATH` and is only consulted for
gmsh-route components, so `--check --component phaseVI_blade` runs without any
gmsh installation. `--check` is the CI/PR gate: it regenerates the component
into a temporary directory, byte-compares the STL and the metadata JSON against
the committed artefacts, and verifies that `PROVENANCE.md` records their current
sha256 values.

Exit codes: `0` clean, `1` stale or failed generation, `2` gmsh missing, not
runnable, or not the pinned version (gmsh route only).

A run with successful generation prints the input sha256 and the STL sha256;
`PROVENANCE.md` must record both (update it after regenerating, then re-run
`--check`).

## Components

| Component | Builder | Notes |
|---|---|---|
| `nacelle` | gmsh (pinned 4.15.2) | hemisphere (`R`, upstream) + cylinder (`R` radius, `6R` length), closed by a flat cap at the downstream end. 2616 triangles (paper target ~2652, −1.4 %). |
| `phaseVI_blade` | pure Python (`src/blade_phasevi.py`) | The NREL Phase VI blade: the 26 committed stations (cylinder root, one transition segment, S809 sections) lofted into 3000 wetted-surface triangles. One STL serves both identical rotor blades. |

### Naming resolution

The rotor-qualified `phaseVI_blade` is the S2 blade component: azimuth is
runtime state (blade2 is `$blade1;` + `azimuthalOffset 180`), so a single STL
serves both blades. The earlier `blade0`/`blade1`/`blade2` reservation is
retired — those names are no longer advertised as outputs (the CLI answers them
with a retired-name error) and no per-blade duplicate STL is committed. A future
MEXICO blade is a separate `mexico_blade` component owned by the
`mexico-validation` change; this registry is the extension point.

Adding a gmsh component means adding `src/<name>.geo` plus one `BUILDERS` entry
in `makeGeometry.py`; a Python component adds `src/<name>.py` with a
`build(stl_path, metadata_path)` entry point. The STL/metadata paths, the
`--check` flow and the CLI help all come from the registry.

## Metadata schema

### `metadata/nacelle.json` (gmsh route)

```json
{
  "component": "nacelle",
  "format_version": 1,
  "generator": {"script": "src/nacelle.geo", "gmsh_version": "4.15.2"},
  "input_sha256": "<sha256 of src/nacelle.geo + parameter block>",
  "units": "m",
  "n_triangles": 2616,
  "parameters": {"R": 1.0, "cylinderRatio": 6.0, "meshSizeRatio": 0.2125},
  "stl_sha256": "<sha256 of stl/nacelle.stl>",
  "nodes": [
    {"index": 0, "normal": [-0.995209, 0.0141688, 0.0967404], "area": 0.0189569}
  ],
  "_reserved": {"blade": {"radial_station": null, "chord_fraction": null}}
}
```

One node per STL triangle, in STL order: `index` is the triangle index (the
order a layout loader sees), `normal` is the outward unit normal of that
triangle, `area` its area. `_reserved.blade` records the pre-S2 placeholder that
the generated blade component replaces; it is kept in the nacelle schema for
byte stability.

### `metadata/phaseVI_blade.json` (Python route)

```json
{
  "component": "phaseVI_blade",
  "format_version": 1,
  "generator": {"script": "src/makeGeometry.py", "builder": "phaseVI_blade"},
  "inputs": {
    "blade_csv": "validation/phaseVI/data/geometry/phaseVI_blade.csv",
    "blade_csv_sha256": "<sha256 of the committed station table>",
    "s809_csv": "validation/phaseVI/data/s809/s809_somers_nlr.csv",
    "s809_csv_sha256": "<sha256 of the committed S809 coordinates>",
    "pitch_deg": 3.0
  },
  "input_sha256": "<sha256 of the input bytes + canonical parameter block>",
  "units": "m",
  "n_triangles": 3000,
  "stl_sha256": "<sha256 of stl/phaseVI_blade.stl>",
  "nodes": [
    {"index": 0, "normal": [-0.995209, 0.0141688, 0.0967404],
     "area": 0.0189569, "radial_station": 0.5083, "chord_fraction": 0.42}
  ]
}
```

One node per STL triangle, in STL order: `normal` is the outward unit normal,
`area` its area, `radial_station` the triangle centroid's span coordinate (m)
and `chord_fraction` the mean of the three vertices' LE-based chord fractions.
There is no `_reserved` block — the blade mapping is populated.

In both schemas, `n_triangles`/`nodes` describe the *surface* nodes the sampler
consumes (the sampler uses triangle centroids as its node set), not the STL's
vertices. Floats are rounded to 6 significant digits (within the float32
resolution of the binary STL).

## Determinism requirements

- The gmsh route is pinned (**4.15.2**, recorded in `metadata/nacelle.json` and
  `PROVENANCE.md`). `--check` refuses to certify regeneration with any other
  version (exit `2`) instead of reporting a false staleness. The Python route
  has no gmsh dependency at all.
- The gmsh mesh seed and options live in `src/<component>.geo`; the parameters
  marked `primary:` are parsed into the metadata and the input sha256. The
  Python route's inputs are the committed CSV files, hashed into `inputs` and
  `input_sha256`.
- The generator re-serializes the triangles in a canonical order (cyclically
  minimal vertex order per triangle, triangles sorted) and writes the binary STL
  itself, with a fixed per-component header and recomputed facet normals. gmsh's
  element ordering is not stable across environments, so without this step the
  same mesh could produce different bytes; with it, the committed STL depends
  only on the mesh geometry.
- `--check` never modifies the tree — it regenerates into a temporary
  directory. Tests rely on this by copying the whole `geometry/` tree to a
  temporary location and corrupting the copy.
- gmsh must be *runnable*, not merely installed: the pip module links
  `libGLU.so.1`/`libGL.so.1`. On SDumont, `module load glu/9.0.2_gnu` (see
  `PROVENANCE.md`). Without it, the nacelle regeneration checks skip with an
  explicit reason; the blade checks never need gmsh.

## Consuming the STLs

`nacelleSurfaceSource` reads `stl/nacelle.stl` directly through OpenFOAM's
`triSurface` (`geometry` key in the `nacelle {}` subdict / standalone
`fvOptions` entry). The STL is in metres, with the downstream end of the body at
the streamwise origin `x = 0` and the nose pointing upstream to `x = -7R`, which
is the frame the validation case in `validation/nacelle-asn/` expects (`R = 1 m`,
`Re = 1000`).

The `phaseVI_blade` STL is staged into a Phase VI run directory as
`constant/triSurface/phaseVI_blade.stl` and referenced through the blade's
`surfaceGeometry` key. It is in metres in the blade generation frame: `+z` is
the outward span (`0.5083 … 5.029 m`), `+y` the reference chord direction
(trailing edge → leading edge before twist/pitch) and `+x = y × z` the section
normal, with the chord-line quarter-chord point on the radial reference line.

The generation recipes, source references and resolved hashes are recorded in
`PROVENANCE.md`; the pure-Python data tests guard the committed artefacts
(nacelle and blade) without OpenFOAM.
